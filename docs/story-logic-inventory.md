# 《算力寡头》剧情逻辑总表

这份文档描述当前代码中的剧情系统，不是新的剧情稿。重写剧情时，优先修改 `src/content/` 中的文案和配置；除非明确需要改变玩法，否则保留事件 ID、选项 ID、章节字段和状态接口。

## 1. 玩家流程

```text
启动
  -> 世界 Intro（6 幕）
  -> 五方选择
  -> 所选势力入场剧情（3 幕）
  -> READY 确认
  -> 主游戏
```

主游戏每个时间周期的当前流程：

```text
完成当前治理额度分配
  -> 推进时间
  -> tick 结算地块/势力/模型漂移
  -> 检查主线剧情
  -> 若有主线：玩家选项
  -> 顾问关系、历史承诺、势力路线更新
  -> 进入 3 点主动治理额度
  -> 调查/投资/协商/审计/动员/公开等主动行动
  -> 利益压力结算
  -> 社会反馈展示
  -> 检查结局、动态危机、配置事件
  -> 若没有弹窗，进入下一周期
```

推进被以下状态阻断：主线剧情、配置事件、结局、章节总结、利益反馈、主动行动阶段、五灯分配未完成。

## 2. 核心资源与剧情的关系

基础 `GameState` 资源：

- `compute`：算力，生产和扩张能力。
- `data`：数据，模型训练和数字劳动产物。
- `stability`：势力稳定度。
- `globalModelDrift`：全局模型漂移。
- `globalStability`：全局社会/基础设施稳定度。
- `infrastructureRegions`：30 个基础设施区域，含算力容量、电力生产、电力需求、数据产出、区域稳定度、区域漂移、控制势力。

五盏灯不是简单属性，而是长期利益方向：

| 灯 | 方向 | 对应势力 | 长期忽视的系统后果 |
|---|---|---|---|
| 产业 | 订单、扩张、资本和技术增长 | 天穹公司 | 订单积压、算力扩张受阻 |
| 秩序 | 规则、听证、审计和协调 | 寰盟 | 规则执行断裂、全局稳定下降 |
| 工棚 | 数据劳动、互助、组织和夜班 | 星火工联 | 数据质量下降、劳动危机 |
| 公开 | 开源、教育、共享、审计 | 棱镜开源社 | 信任危机、模型漂移上升 |
| 民生 | 医疗、教育、养老、公共服务 | 赤衡共同体 | 公共服务危机、稳定度下降 |

每个周期玩家分配总计 100 点五灯投入。某灯本章占比达到 25% 且最高时为“最亮”；低于或等于 10% 时为“被忽视”。

## 3. Intro 剧情

文件：`src/content/intro.ts`。

### 世界 Intro

当前 6 幕：

1. 全球算力交易指数、寰盟协调会、星火工联跨境行动。
2. 广场倒计时：距离奇点 365 天，第三次重置。
3. 外卖员听见客服机器人，抬头看算力塔。
4. 机房耗电量相当于小城市三年用电。
5. 数据工人完成第 4000 条语音标注。
6. 收束句：没有人知道奇点会不会来，但所有人都在下注。

结尾有一个不改变数值的初始文案 flag：

- `believer`：相信奇点真的会来。
- `skeptic`：认为奇点只是说法，重要的是现在。

### 五方选择与入场

选择页使用 `factionProfiles`，不能重复定义势力数据。选择后播放 3 幕势力剧情：

- 天穹公司：董事会任命、机房巡视、效率不解释自己。
- 寰盟：多国协调会、曼努埃拉提醒守住桌子、待签公共条例。
- 星火工联：跨境工棚、地下硬盘网络、谈判还是行动。
- 棱镜开源社：模型开源争论、匿名捐款、停在半句的下一步计划。
- 赤衡共同体：公共算力站图纸、山区机房、核对电力余量。

Intro 状态保存在 `sessionStorage`，不进入 `GameState` 和存档结构。

## 5. 五方专属剧情

文件：`src/content/faction-story.ts`，只会加载当前玩家所选势力的 3 个事件。

| 势力 | 事件链 | 核心路线 | 命脉 / 隐患 |
|---|---|---|---|
| 天穹公司 | `CONSORTIUM-T1/T2/T3` | 上线期限、艾米莉辞职、扩张与数据红利 | 控制力 / 裂缝 |
| 寰盟 | `SOVEREIGN-C1/C2/C3` | 无预算听证、资本交易备忘录、强制执行令 | 公信力 / 空转 |
| 星火工联 | `LABOR-S1/S2/S3` | 数据事故、设备借用、净网撤退 | 人心 / 暴露 |
| 棱镜开源社 | `PRISM-P1/P2/P3` | 匿名捐款、社区争论、代码被用于监控 | 开放度 / 失控 |
| 赤衡共同体 | `SOCIALIST-H1/H2/H3` | 公共站选址、方案审批、公共站审计 | 民生保障 / 僵化 |

每个专属选择产生 `FactionArcChange`：

- `lifeline`：势力路线命脉。
- `liability`：路线隐患。

这些不是基础 `GameState` 资源，但会参与最终叙事结局。

## 6. 动态剧情：五灯反馈

文件：`src/content/reactive-story.ts`。

### 反应类型

- `resonance`：某灯长期最亮，优势开始提出新的代价。
- `grievance`：某灯长期被忽视，被压下的问题回来。
- `crisis`：玩家当前势力资源或模型状态进入危机。

### 事件目录

| 类型 | 事件 |
|---|---|
| 最亮回响 | `RA1` 订单如潮、`RA2` 整齐的文件、`RA3` 越来越多的手、`RA4` 热闹的社区、`RA5` 通电的村子 |
| 被忽视回响 | `RB1` 订单去哪了、`RB2` 被推迟的听证、`RB3` 冷灶、`RB4` 掉线的服务器、`RB5` 停摆的站 |
| 资源危机 | `RC1` 能源见底、`RC2` 账户见红、`RC3` 民心跌落、`RC4` 数据外泄，另有模型反馈循环危机 |

反应事件只看当前玩家的五灯状态和当前势力资源，因此它们是“玩家路线反馈”，不是固定章节。

## 7. 动态危机

文件：`src/content/dynamic-crises.ts`。

动态危机根据压力、主动行动、政策遗产、顾问关系和资源计算因果评分，达到阈值 7 才出现。当前危机：

- `dynamic-labor-rupture`：数据劳动断裂。
- `dynamic-capacity-debt`：算力扩容后的债务。
- `dynamic-trust-blackout`：无人相信的公告。
- `dynamic-coordination-gridlock`：所有人都在等批复。
- `dynamic-model-feedback-loop`：模型开始引用自己。

危机不是完全随机，但当前动态危机选择器按评分优先，并由当前玩家势力承接决策。它们可产生跨方资源影响、模型漂移和稳定度变化。

## 8. 配置事件

文件：`src/content/events.ts`；运行时：`src/content/event-runtime.ts`。

这些是基于 `GameState` 条件的独立危机事件，每个事件有：

- `faction`：主视角势力；当前修复后只有该势力的玩家会看到它。
- `theme`：劳动冲突、算力垄断、数据泄露、模型漂移、开源公地。
- `trigger.all`：必须全部满足。
- 两个选项，每个选项通过纯函数返回新 `GameState`。

当前事件：

| ID | 主视角 | 标题 | 触发核心 |

| `ghost-workers-ledger` | 星火工联 | 幽灵工时总账 | 劳动意识高，星火维修走廊稳定低 |
| `blackout-auction` | 天穹公司 | 停电拍卖 | 天穹算力高，全局稳定低 |

| `citizen-shadow-corpus` | 寰盟 | 公民影子语料库 | 寰盟监控指数高，区域漂移高 |
| `wasteland-memory-market` | 赤衡共同体 | 废土记忆市场 | 区域漂移高，天穹数据低 |

## 9. 主动行动与利益压力

主动行动在 `src/core/systems/strategic-actions.ts` 中定义，每个周期有 3 点治理额度。行动类型包括调查、投资、协商、审计、动员、公开、调整资源和干预区域等。

行动主要留下 `pressureTags`，不一定直接加资源：

- 审计/创新延迟：产业压力。
- 公开/暴露：秩序压力。
- 动员/数据需求：工棚压力。
- 协商兑现：公开压力。
- 基础设施扩张：民生压力。

`settleInterestPressures` 在周期结算时把当前五灯投入、行动标签和历史承诺转成五类压力。压力达到 25/50/75 时依次为持续压力、危机、断裂，并对对应势力、地块、全局稳定或模型漂移造成后果。

## 10. 顾问系统

每个势力有两名顾问，每名顾问有：利益方向、立场、偏好政策标签、反对标签、信任度和关系历史。

当前顾问：

- 天穹：阿迪蒂亚·梅赫塔（稳运转）、朴世勋（管舆论）。
- 寰盟：曼努埃拉·科雷亚（讲理想）、奥斯曼·亚尔琴（讲证据）。
- 星火：玛尔塔·索萨（稳扎稳打）、塔尼娅·卡明斯基（要有行动）。
- 棱镜：泽田真司（再检查）、阿德奥拉·巴洛贡（先发出去）。
- 赤衡：陆知行（按流程）、苏晚照（先试试）。

顾问展示在当前势力剧情中。漂移达到 20 后，按确定性哈希让部分顾问信号进入“模型转述”，从而不再完全可靠。信任变化：被选中的顾问 +10，未被选中的同阵营顾问 -4；关系记录进入终局因素。

## 11. 历史承诺 / 政策遗产

文件：`src/content/policy-legacies.ts`。

只有少数专属事件会创建政策遗产：

- 天穹 `CONSORTIUM-T1`：扩张优先 / 安全先于期限。
- 寰盟 `SOVEREIGN-C1`：公开听证 / 借力资本。
- 星火 `LABOR-S1`：共同问责 / 内部消化。
- 棱镜 `PRISM-P1`：资源先行 / 来源可追溯。
- 赤衡 `SOCIALIST-H1`：先让服务落地 / 基础设施先行。

后续对应的第三段专属事件会把 active 承诺标记为 `honored` 或 `broken`。政策标签会改变利益压力，例如扩张优先加剧工棚压力，企业依赖削弱公开方向，服务优先缓解民生等待。

## 12. 结局

两层结局逻辑：

### 第一层：系统是否存活

- 玩家势力稳定度归零：势力崩溃。
- 全局漂移达到系统阈值：系统崩溃。

### 第二层：系统最终变成什么

`evaluateNarrativeEnding` 综合：五灯长期分配、势力命脉/隐患、合作选择、主动协商次数、动态危机处理方式、历史承诺是否背离、顾问关系、全局漂移和 E41 选择。

当前结果包括：碎片化网络、共同网络，以及按主导灯和势力路线生成的社会形态，如集中式、公共化、开放共享、劳动者代表进桌等。

`endingFactors` 是现有结局展示的摘要。若后续需要“证据墙”，应从 `StoryProgress.choices`、`PolicyLegacyState.records`、`AdvisorRelationshipState.history`、`EventDecisionState.records` 读取，而不是重新创造一套历史状态。

## 13. 给 Claude 的重写约束

1. 保留代码 ID：`P1`、`E01-E41`、`E20′`、`M01-M08`、五方专属 ID、`RA/RB/RC`、动态危机 ID、配置事件 ID。
2. 保留所有选项 ID，除非同时修改运行时测试、政策遗产映射和结局读取逻辑。
3. 一个事件必须明确：主视角势力、公共影响对象、触发条件、两个或三个选项、即时收益、即时代价、历史回响。
4. 不要把“所有势力都会受影响”误写成“所有势力都应该看到同一事件”。玩家看到的是当前势力可负责、可判断、可承担的冲突。
5. 不要把五灯写成抽象升级树；每一盏灯必须对应社会利益和长期压力。
6. 不要让选择只改变即时数字。重要选择必须通过已有 `StoryProgress.choices` 或 `PolicyLegacyState` 留下可读取的历史。
7. 公共危机可以跨势力，但必须明确谁提出问题、谁拥有决策权、其他势力如何受影响。
8. 事件文本不要加入 UI 指令、组件名、实现说明；文案文件只描述世界、人物、问题、选择和结果。
9. 优先重写 `src/content/story-events.json`、`src/content/faction-story.ts`、`src/content/reactive-story.ts`、`src/content/dynamic-crises.ts`、`src/content/events.ts`，不要先重写 UI 或 `GameState`。
10. 修改完成后，运行 `pnpm typecheck`、`pnpm test -- --run`、`pnpm lint`、`pnpm build`。
