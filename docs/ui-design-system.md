# 《算力寡头》UI Design System

## 视觉定位

日常界面是冷静、制度化、高信息密度的未来政治与计算基础设施终端。事件、章节与结局属于叙事广播节点，可以使用旧时代宣传档案的构图、纸张、油墨和印刷错位语言。两种模式共享信息结构，但不共享视觉强度。

故障效果只表达模型漂移，不能作为常驻装饰。青色与品红只属于故障层，不承担普通按钮、势力或五灯的基础配色。

## Token 层级

`src/styles/tokens.css` 是视觉变量的唯一来源，按以下层级组织：

1. `--ds-ink-*`、`--ds-paper-*` 等原始色板。
2. `--ds-color-*` 语义颜色，组件只应消费这一层。
3. `--ds-lamp-*` 五种社会利益方向。
4. `--ds-text-*`、`--ds-space-*`、`--ds-radius-*`、`--ds-shadow-*`、`--ds-duration-*` 和 `--ds-z-*`。
5. `--terminal-*`、`--status-*` 与 shadcn HSL 变量是迁移期兼容别名，新组件不要继续扩展这一层。

Tailwind 3 的主题映射位于 `tailwind.config.ts`。项目升级 Tailwind 4 之前，不使用 `@theme`。

## 颜色规则

- 墨黑用于画布与终端表面。
- 米白用于正文与主要数据。
- 暗红用于系统危险、政治冲突和不可逆后果。
- 深靛蓝用于制度信息、档案与公共系统。
- 褪黄用于待处理事项、资源约束与主要操作。
- 青色和品红仅用于模型漂移造成的 RGB 分离与数字故障。
- 五灯使用专属社会方向 token，不能直接复用通用成功或错误色。

## 字体与密度

- `--font-display`：海报感标题、章节名、势力名。
- `--font-interface`：按钮、导航、面板标题和正文。
- `--font-data`：数字、时间、资源、编号和系统状态。
- 可交互文字原则上不得低于 `--ds-text-xs`，长段中文不得使用全大写或过宽字距。

## 组件规范

后续组件应收敛为以下基础类型：

- `Button`：primary、secondary、ghost、danger、icon。
- `Panel`：日常终端信息容器。
- `DialogShell`：统一遮罩、标题栏、焦点管理和移动端滚动。
- `NarrativePanel`：事件、章节、结局使用的宣传档案容器。
- `MetricReadout`、`DataRow`、`ProgressTrack`：资源与状态数据。
- `StatusLamp`、`StatusBadge`、`AlertStrip`：状态和警报。
- `DecisionOption`：包含代价、支持者和后果提示的决策入口。
- `EventArtworkFrame`：叙事插画及其故障覆盖层。

面板不能嵌套装饰性面板。边框、状态条和底色必须承担分组、层级或状态意义。

## 漂移等级

- `0–30`：正常，无扫描线、噪点或 RGB 偏移。
- `30–50`：轻微扫描线，少量关键读数出现轻微 RGB 偏移。
- `50–70`：局部文字错位，地图节点出现受控闪烁。
- `70–90`：明显数据冲突、面板撕裂和局部失真。
- `90+`：全局严重故障，但真实数值、关键操作和焦点状态必须保持可辨识。

漂移等级由游戏状态统一映射到根节点属性。动画关闭设置可以减少运动，但不能隐藏风险状态本身。

## 迁移顺序

1. Design Tokens 与 Tailwind 映射。
2. 日常入口、主界面和通用弹窗。
3. 五灯、势力和地图语义色。
4. 模型漂移五级视觉反馈。
5. 事件、章节和结局的宣传档案模式。
6. 删除兼容变量和剩余硬编码视觉值。
